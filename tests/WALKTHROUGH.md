# 整體專案走查

## 何時執行

**只有維護者明確要求「跑走查／完整走查／整體走查」才執行本清單。**

修改程式、推送、進版、打包或發布版本，都不自動觸發完整走查，也不主動加跑。日常修改仍依 AGENTS.md 做相關測試與本次修改的必要驗證；這不代表要跑整份清單。

## 目的與取捨

觀察店員／管理者完成日常任務時，UI回應、提示、焦點、內容保留與下一步是否清楚。依2026-11-08兩輪實際結果，移除已驗正常且低風險的例行操作，保留跨步驟連動、未儲存內容、狀態切換及複雜子視窗。

- 每項只選一個代表性日常流程，不排列組合、不逐一測所有按鈕與主檔。
- 同次走查能由一段流程一起觀察的項目合併操作，不另跑一輪。
- 同一版本已驗正常、未受後續改動影響的部分直接沿用紀錄；沒有新的驗證必要就略過並註明。
- 已知且尚未修改的問題直接帶入結果，不反覆重現；修正後才回看該互動。
- 不刻意連點、競速、製造錯誤、等待閒置逾時或窮舉邊界。自然碰到查無資料、重複項目或權限提示時，觀察是否清楚即可。
- 版面只看本輪變更或有疑慮的畫面；涉及版面時仍依 AGENTS.md 補看1278×720，不把所有正常頁面與彈框各量一次。

## 保留的7項重點

- [ ] **批次建檔**：選一組規格／型號，產生預覽、編輯一列並建立；觀察預覽內容、必要提示與完成後刷新。不重跑所有規格型別、組合數量與條碼排列。
- [ ] **設定的未儲存內容**：選一個有批次儲存或排序的區塊，修改後操作取消或切換；觀察提醒及內容是否保留。不逐一重跑各主檔的新增、改名、停用與刪除。
- [ ] **待處理商品修正**：有現成待處理商品時，從原因提示進入編輯、修正並回清單，觀察狀態與可用操作。沒有現成案例就記不適用，不為走查製造問題資料。
- [ ] **收銀連動**：一筆日常交易觀察實售價／折扣、會員選取、應收／實收及完成後內容；不再三種付款各結一單，也不重跑已正常的會員維護。
- [ ] **盤點狀態切換**：選一張單操作送審後的抽回或退回重盤，觀察欄位能否編輯、提示與數量顯示。不列舉所有作廢、權限與庫存情境。
- [ ] **返修與返新**：選一張返修單做一次分批返新或結案／撤回，觀察剩餘件數、狀態與查詢畫面是否一致。順帶觀察相關張數，不重跑一般退貨及整套標籤清單。
- [ ] **複雜子視窗互動**：以上流程順帶觀察一個本輪變更或較複雜的子視窗：焦點、儲存／取消、關閉後解鎖與刷新；有版面變更或疑慮才量測。不要為每種視窗各開一套相同檢查。

## 不再列入固定走查

- 一般開啟／重開、登入／登出／改密碼、等待10分鐘閒置登出。
- 已驗正常的主檔逐項新增／修改／停用／刪除、普通搜尋篩選、單純展開收合。
- 三種付款各跑一單、一般進貨／一般退貨各分支、標籤清單與預覽的完整排列。
- CSV存檔、掃描槍硬體、貼紙機實體列印及硬體故障。
- 直接呼叫內部服務、修改資料庫、故障／延遲注入、底層資料檢查、備份輪替、資料庫工具、打包與更新工具測試。

上述功能若本次有修改，仍做該改動必要的相關驗證；不因它存在於專案，就納入每次完整走查。

## 執行與紀錄

使用獨立匿名測試資料庫與暫存輸出，操作真實 pywebview，不開 repo 原始 pos.db。結束關閉本次程序並清理暫存資料。

紀錄放在被忽略的 docs/walkthrough/日期_版號.md，只記本輪實際觀察、沿用證據、略過理由與問題。狀態用「正常／發現問題／沿用／不適用／未完成」，不以改小清單把過去未驗證項目改成通過。自動測試結果另記，不為走查重跑沒有必要的完整測試。

2026-11-08已知問題：款式編輯中的既有停用選項顯示「將重新啟用」，儲存後仍停用。未修正前沿用這個結果，不重現；修正後再看提示與實際狀態是否一致。
